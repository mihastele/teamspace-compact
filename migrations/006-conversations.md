# 006 — Page and task conversations

Additive lazy schema: `workspaces/{workspace}/notes/{note}/comments/{comment}` and the equivalent task subcollection. No live database changed or backfill required. Maintain TypeScript models manually; no generated Firestore types exist. Clean emulator fixtures verify the new schema and access control from scratch.

Each immutable message stores body (trimmed, 1–4,000 characters), authorId/authorName derived from verified authentication, trusted-server createdAt timestamp, deleted flag, trusted mentions (`uid`, membership-derived displayName), operationId UUID and SHA-256 digest of the exact request body. IDs are SHA-256 of authenticated UID plus operation UUID scoped to their parent. Duplicate delivery returns the original message, including its tombstone; changed payload with reused identity fails. The timestamp determines display order only, never correctness. Equal timestamps use document-ID ordering. Mention tokens `@{uid}` must identify current same-workspace members, with at most ten distinct people; all membership reads and creation share the parent/member transaction.

Browser reads require current workspace membership and a live, non-deleting parent. Browser writes are denied. Trusted POST checks membership, live parent, body/identity limits, and per-user limit of 20 posts/minute. DELETE is author-only, with 30 deletes/minute. Deletion replaces body with an empty string and mentions with an empty list while retaining author/time/identity/digest; tombstones prevent old retries from resurrecting deleted text. No message editing or owner moderation endpoint is added.

The reusable client listener requests only the latest 50 comments using createdAt descending then document ID descending; single-field createdAt indexing supports this implicit same-direction tie-break. No composite index is needed. Body and mentions are exempt from indexing. Older comments remain stored but have no pagination UI in this first slice.

Retention/export/deletion: comments persist until the parent is deleted, except author-deleted text is erased immediately. The digest is operational retry metadata and is not an export of text. Complete workspace export must include live messages/mentions and deleted-message metadata without reconstructing text; full export is still a separate open feature. Parent deletion fences new operations, recursively removes comments before removing either note or task, and remains retryable after cleanup failure. History restore leaves conversations intact. No notification delivery, email, inbox, or account-wide data-retention policy is added by mentions.

Deploy rules/indexes before compatible API/client. Rollback disables conversation UI while retaining subcollections, and must preserve default-deny browser writes and trusted deletion cleanup. No dependency or authentication-provider change.

Device-local recovery: draft and uncertain request body/UUID are stored per account/workspace/entity before transmission. One Web Lock owns that draft across tabs. This browser copy can remain after membership removal or parent deletion so unsent work can be downloaded; it is not cloud conversation data. Clearing browser storage removes it. An uncertain retry rejected after revocation/deletion retains its original UUID because that rejection cannot prove the original attempt never committed. Other tabs remain read-only for composing until the owner releases the lock; different accounts have independent writers.
