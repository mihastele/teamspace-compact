# 017 — Empty block containment foundation

Adds a workspace-scoped block identity, optional parent, type, sortable position and revision. A null parent means a top-level block. The same-workspace parent key and a workspace-serialized trigger reject missing parents and containment cycles; identities cannot be changed. Positions sort using the C collation with block ID as a deterministic tie-breaker. This step creates no application writer and does not copy, delete or modify existing notes, tasks, projects, collaboration state, attachments or history. It is not the data migration or a completed block editor.

Member reads use the existing confirmation and workspace membership RLS policy. Anonymous and direct authenticated/service-role writes are denied. Future trusted mutations must authenticate and authorize, handle revision conflicts and retries, and use transactions; they must not bypass the containment trigger. Future deletion writers must also lock the workspace before changing the graph; there is no deletion writer in this increment. Workspace deletion cascades these rows; deleting a parent alone cannot leave children orphaned. User-facing block deletion, reference behavior and history restoration are still decisions before a writer is introduced.

The table holds no content until a future authorized writer/migration exists. Its eventual workspace export must include block identities, parent, order, type and revision together with associated content and relationships; complete workspace export remains an open project feature. The migration itself adds no attachment or collaboration state. Before migration of existing data, verify backup and restore, define mapping and preserve old offline edits according to the pending user decision. Do not apply it to staging merely as part of development.

The generated row type comes from the actual PostgreSQL catalog via `node scripts/generate-block-types.mjs --container <test-container> --write`; the integration suite checks it against the clean schema. Run the generator only against an owned test container with this migration applied. Clean and populated migration, RLS, race and cascade tests run on disposable PostgreSQL fixtures, not the configured installation.
